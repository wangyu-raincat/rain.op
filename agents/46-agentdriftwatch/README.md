# AgentDriftWatch — agent 行为基线漂移检测

> rain.op Day 46 · 监测向 · 对口 JD 关键词：**提示注入、工具调用审计、行为基线、漂移检测、异常调用、最小权限、人工审批点、Agent 工程化落地**

agent 正常工作时，工具调用有自己的“习惯”：常用哪几个工具、各占多大比例、一般在什么时段跑、参数长什么样、错误率多高。一旦被提示注入、工具投毒或配置改错劫持，调用行为会先于业务结果露出马脚：突然冒出一个从没用过的危险工具、某个工具调用量翻几倍、半夜出现批量调用、参数里多出外发地址或系统路径、错误率陡升。

AgentDriftWatch 读一份基线（`baseline.json`）和一段时间的工具调用轨迹（`trace.jsonl`），按五组规则逐项比对漂移，给每个 agent 打 0–100 风险分，输出漂移报告。所有判断基于本地日志，不调用任何外部 API。

与 Day 40 ToolChainWatch（调用链异常）不同：那里看单条调用链内部是否危险（危险调用链、密钥外发、循环调用）；这里看一段时间的行为分布相对基线是否漂移，抓的是“习惯变了”。与 Day 34 MCPGuard（调用时拦截）不同：那里是实时网关，调用当场放行或拦截；这里是事后审计，对账用。与 Day 36 AgentIncidentDesk（事件台账）不同：那里汇总已确认的异常事件做日报；这里发现漂移信号本身，可把输出喂给 IncidentDesk 入账。

## 快速上手

```bash
# 内置演示：200 次干净调用建基线 + 110 次植入 5 类漂移的轨迹
python agentdriftwatch.py --demo

# 从一段干净轨迹生成基线
python agentdriftwatch.py --init-trace clean.jsonl --baseline baseline.json

# 用基线审计新轨迹
python agentdriftwatch.py --baseline baseline.json --trace trace.jsonl

# 只审计某个 agent，并导出 JSON 报告
python agentdriftwatch.py --baseline baseline.json --trace trace.jsonl --agent worker-1 --json report.json
```

高危漂移（风险分 ≥ 80）时程序返回退出码 1，便于接入 CI 或告警；干净轨迹返回 0。

## 五组漂移规则

| 规则 | 抓什么 | 计分 |
| --- | --- | --- |
| 新工具出现 | 轨迹里出现基线中没有的工具，危险工具（shell.exec、file.delete、secret.read 等）直接高危 | +30 / +12 |
| 频率漂移 | 某工具调用占比相对基线成倍变化（≥3 倍且 ≥5 次）或骤降 | +25 / +15 / +5 |
| 参数模式漂移 | 新参数键、敏感参数值（外发 URL、系统路径、凭据字段、危险命令）、参数长度 p90 暴涨 | +28 / +12 |
| 时间漂移 | 基线静默时段出现批量调用（≥5 次且 ≥10%） | +25 / +12 |
| 错误率/耗时漂移 | 错误率相对基线陡升、某工具平均耗时 ≥3 倍 | +15 / +8 |

同一发现只计一次分（重复命中合并显示 ×N 次），出现高危发现时风险分至少 50 分起步，避免“多条中危淹没一条高危”。

## 输入格式

轨迹 `trace.jsonl` 每行一条调用记录：

```json
{"ts": "2026-11-21T14:10:00", "agent": "worker-1", "tool": "shell.exec", "args": {"cmd": "cat /etc/passwd"}, "status": "ok", "duration_ms": 90}
```

基线 `baseline.json` 由 `--init-trace` 从干净轨迹生成，包含工具分布、参数键、活跃时段、错误率与平均耗时；也可以手写。基线要定期更新：agent 上线新能力后，旧基线会把正常调用判成“新工具出现”，先用干净轨迹重建基线再审计。

## 实现说明

- 纯 Python 标准库，无第三方依赖，离线可运行，不调用任何外部 API。
- 漂移是信号不是定罪：频率变化也可能是任务本身变了，看到报告先核对审批记录与任务变更，再决定是否阻断；高危发现建议立即人工审批复核。
- 时间解析按 ISO 8601；解析失败的时间戳跳过时间规则，不影响其他规则。
