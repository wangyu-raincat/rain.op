# SSRFWatch

服务端请求伪造（SSRF）探测检测：分析 Web 访问日志，识别打向“帮用户抓 URL”类入口（`?url=`、`?uri=`、`?target=` 等参数）的 SSRF 探测，按 IP 打 0–100 风险分，输出告警与处置建议。纯 Python 标准库，离线可运行。

## 它检测什么

| 规则 | 例子 | 风险 |
| --- | --- | --- |
| 云元数据探测 | `?url=http://169.254.169.254/latest/meta-data/`、`metadata.google.internal`、阿里云 `100.100.100.168` | 偷云实例临时凭证 |
| 内网地址探测 | `?uri=http://127.0.0.1:6379/`、`192.168.1.10:8080/admin/` | 探内网管理后台、数据库、缓存 |
| 危险协议 | `file:///etc/passwd`、`gopher://127.0.0.1:6379/` | 读本地文件、打内网协议 |
| 绕过形态 | 十进制 IP `2130706433`、十六进制 `0x7f.0.0.1`、双重编码、`http://公网@内网地址` | 绕过“只禁内网 IP”字面校验 |
| 内网敏感端口 | 目标端口 22/6379/3306/5432/2375/9200 等 | 针对性踩点内网服务 |
| 内网敏感路径 | 目标路径 `/admin`、`/actuator`、`/env`、`/console` | 找内网管理面 |
| 枚举爆发 | 同一 IP 命中 3 种以上不同 SSRF 信号 | 系统性踩点 |
| 疑似成功取回 | 元数据/内网目标返回 200 且响应体 ≥ 1KB | 服务端可能真的发起了内网请求 |

合法预览服务只抓公网链接时只记低分（每条 5 分），不会误报成高危；普通分页参数（如 `?page=2`）因值不像 URL 会被直接忽略。

## 怎么跑

```bash
# 离线演示（含合成攻击流量：正常用户 + 合法预览 + 2 个攻击者）
python ssrfwatch.py --demo

# 分析自己的日志（Nginx/Apache combined 格式）
python ssrfwatch.py --log access.log --json-out alerts.json

# 只生成演示日志
python ssrfwatch.py --demo-log demo.log
```

## 输入格式

每行一条 Nginx/Apache combined 格式访问日志，例如：

```text
203.0.113.91 - - [28/Oct/2026:09:00:10 +0800] "GET /api/fetch?url=http://169.254.169.254/latest/meta-data/ HTTP/1.1" 200 3120
```

无法解析的行会被跳过。日志里没有响应体，因此“疑似成功取回”只是加分信号，不是定罪证据；命中规则也不等于确认 SSRF 成功，请结合服务端出站请求日志与 IP 归属复核。

## 处置清单（命中高危时）

1. 若命中云元数据探测：立即轮换实例角色临时凭证，检查云元数据服务访问记录，确认服务端是否真的请求了元数据地址。
2. 抓取入口只允许 http/https：校验前先完整解码、解析主机为 IP 再判断，拒绝内网段、回环地址、十进制/十六进制/八进制 IP 与 `@` 混淆主机。
3. 校验要覆盖重定向链：目标 URL 跟随重定向后落点同样需要校验，防止短链/开放重定向绕过。
4. 若疑似成功取回内网内容：按内网信息泄露处置，复核该时间段的服务端出站请求日志与内网服务访问记录。
