# FireboxWatch

WatchGuard Firebox 严重漏洞探测嫌疑检测：分析 Firebox 日志，识别与 2026-10-27 批量公告中 7 项严重漏洞对应的服务异常征兆，按源 IP 打 0–100 风险分，输出告警与处置建议。纯 Python 标准库，离线可运行。

## 它检测什么

这 7 项漏洞厂商称无已知在野利用，修复版本为 Fireware OS 2026.4 / 12.12.4（T15/T35 用 12.5.22）——**补丁版本以 WatchGuard 厂商 advisory 复核为准**，本工具不判定设备是否已打补丁。

| 信号 | CVE | CVSS | 日志征兆 |
| --- | --- | --- | --- |
| AD 认证服务崩溃/异常 | CVE-2026-112709、CVE-2026-112710 | 9.2 | AD 认证服务（admd）在登录前请求后崩溃/重启、堆溢出 |
| SIP 代理异常 | CVE-2026-93857 | 9.2 | SIP 代理畸形报文、解析错误、崩溃突发 |
| FireCluster 非集群同步尝试 | CVE-2026-93865 | 9.2 | 非集群成员 IP 发起未认证同步、同步被拒绝 |
| Access Portal 异常请求 | CVE-2026-93866 | 9.2 | Portal 超大/畸形请求、整数溢出、越界写征兆 |
| 日志服务崩溃/断档 | CVE-2026-103593 | 9.1 | 日志服务崩溃、停止、日志断档 |
| WireGuard 配置处理异常 | CVE-2026-103594 | 9.5 | WireGuard 配置解析错误、超大配置、栈溢出 |
| AD 登录前认证失败爆发（辅助信号） | CVE-2026-112709、CVE-2026-112710 | 9.2 | 同一 IP 登录前认证失败 ≥ 5 次 |

**WireGuard 项的可达条件与其余几项不同**：据公开报道，它需要经过 Firebox 与 WatchGuard Cloud 之间的 TLS 解密通道才可达，不等于任意外网未认证直达；告警建议里会单独注明，不要把它当成普通外网未认证 RCE 来处置。

同一 IP 命中 3 种以上不同信号时额外加分（系统性探测嫌疑）；同一信号重复出现也加分，上限 100 分。无源 IP 的设备级事件（如日志服务本机崩溃）会单列提示，不计入任何 IP 的风险分。

## 怎么跑

```bash
# 离线演示（含合成攻击流量：正常流量 + 3 个可疑 IP + 1 条设备级事件）
python fireboxwatch.py --demo

# 分析自己的 Firebox 日志
python fireboxwatch.py --log firebox.log --json-out alerts.json

# 只生成演示日志
python fireboxwatch.py --demo-log demo.log
```

## 输入格式

每行一条 Firebox syslog 风格日志，程序取行内第一个 IPv4 地址作为源 IP，例如：

```text
2026-10-29 09:01:10 firebox admd[101]: Active Directory authentication service crash (heap buffer overflow) pre-auth request from 203.0.113.45
```

无法解析或不含信号的行会被跳过。日志格式因 Fireware 版本与导出方式而异，信号关键词可能需要按实际日志微调。

## 处置清单（命中高危时）

1. 先确认补丁：对照 WatchGuard 厂商 advisory，确认各 Firebox 是否已升级到 2026.4 / 12.12.4（T15/T35 为 12.5.22），未打补丁的先升级。
2. FireCluster 信号最优先：核查集群互联口是否暴露给非集群地址，确认集群成员配置未被改动。
3. 日志断档先补采：日志服务崩溃会掩盖其他攻击痕迹，恢复服务并补采该时段设备侧日志后再回查。
4. WireGuard 信号单独定级：核查云侧 TLS 解密通道与配置下发记录，不要直接按外网未认证 RCE 处置。
5. **这些信号只是探测嫌疑，不是入侵定论**：服务崩溃也可能由配置错误或异常流量触发，定级前请结合补丁版本、时间窗口与设备侧崩溃记录复核。

## 边界

- 本工具只分析日志，不向任何地址发请求、不做主动探测。
- 命中规则不等于确认漏洞被利用：厂商称这 7 项目前无已知在野利用；日志征兆只能说明“值得查”，不能证明入侵成功。
