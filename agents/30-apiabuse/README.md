# APIAbuseWatch API 滥用 / 批量抓取检测

分析 Web 访问日志中的 API 请求，按源 IP 聚合，用五组启发式规则打 0–100 风险分，
识别高频调用、接口枚举、错误爆发、批量数据拉取和密钥轮换试探。纯 Python 标准库，
离线可运行，不发起任何网络请求。

## 它是做什么的

单个 API 请求往往都合法，聚合成“同一 IP 的行为”才现形。APIAbuseWatch 检查五组信号：

| # | 规则 | 说明 |
| --- | --- | --- |
| 1 | 高频调用爆发 | 5 分钟内 API 请求 ≥ 120 次即满分（30 分） |
| 2 | 端点枚举 | 访问不同 API 端点 ≥ 20 个即满分（25 分） |
| 3 | 错误爆发 | 4xx 占比 ≥ 50% 即满分（20 分）；被限流 429 后仍继续请求会记入证据 |
| 4 | 批量数据拉取 | 分页遍历到第 50 页，或导出/下载端点调用 ≥ 10 次（15 分） |
| 5 | 密钥轮换试探 | 同一 IP 使用不同 API Key ≥ 5 个即满分（10 分） |

风险分 ≥ 70 为高危，40~69 为中危。出现高危告警时程序按设计返回退出码 1，
便于接入定时任务或告警脚本。

## 怎么跑

```bash
# 内置演示：1 个正常用户、1 个高频抓取者、1 个端点枚举者
python apiabuse.py --demo

# 分析自己的日志（Apache combined log 格式，API 路径需含 /api/）
python apiabuse.py -i access.log -o alerts.json

# 附带的演示日志文件
python apiabuse.py -i sample.log
```

## 输入格式

每行一条 Apache combined log，API 请求需满足：

- 请求路径含 `/api/`（不区分大小写）；
- API Key 从查询参数 `api_key`、`apikey`、`key`、`token`、`access_token` 中提取（可选，
  没有也能跑，只是规则 5 无法触发）；
- 分页页码从查询参数 `page` 中提取（可选）；
- 状态码：4xx 计为错误，429 计为被限流；
- 端点归一化：去掉查询串，纯数字路径段替换为 `{id}`，例如
  `/api/v1/users/123` 和 `/api/v1/users/456` 归为同一端点。

示例：

```
203.0.113.7 - - [03/Nov/2026:20:10:01 +0800] "GET /api/v1/users?page=12&api_key=key-scraper HTTP/1.1" 200 8192 "python-requests/2.31"
```

## 局限

- 启发式规则可能误报：正常的数据同步、压测、批量导入也会触发高频或深分页，
  上线前请按业务基线调整阈值（代码顶部的常量）；
- 日志里没有 Key 时规则 5 不生效；Key 出现在日志查询串里本身就有泄露风险，
  生产环境建议先脱敏再分析；
- 只分析日志文件，不会向示例 IP 发起任何网络请求。
