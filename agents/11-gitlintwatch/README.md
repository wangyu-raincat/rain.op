# GitLintWatch 🛡️

针对 **CVE-2026-97229**（GitLab 自建版 CI/CD 正则编译器整数溢出、未授权 RCE，CVSS 10.0）的
HTTP 日志离线启发式检测：从 GitLab 访问日志 / `production.log` 里找出疑似在探测 CI lint 端点的源 IP，
按 IP 打 **0–100 风险分**，并给出命中的规则和示例日志行。

只做检测与评分，**不含任何可复现利用的正则载荷**；演示数据均为合成日志。

## 背景一句话

PoC 已于 2026-10-13 公开，互联网上仍有大量自建 GitLab 跑在受影响版本。
攻击链在日志侧留下的痕迹是：**未授权调用 CI lint 端点 + 正则里内嵌内联注释绕过扫描 + UTF-8 路径**。
这个 agent 就是抓这些痕迹的。

## 怎么跑

纯 Python 标准库，无第三方依赖：

```bash
cd agents/11-gitlintwatch
python gitlintwatch.py --demo        # 内置合成日志演示，离线可跑
python gitlintwatch.py --list        # 列出 5 组检测规则
python gitlintwatch.py access.log    # 分析自己的日志文件
python gitlintwatch.py access.log --json   # JSON 输出，方便接入 SIEM
```

日志行格式（空格分隔，一行一条）：

```
<ISO时间> <源IP> <用户名|-代表匿名> <方法> <路径(含查询参数)> <状态码> <UA...>
```

示例：

```
2026-10-14T10:00:25 203.0.113.7 - POST /api/v4/projects/42/ci/lint?ref=dev 200 python-requests/2.31
```

## 5 组检测规则

| 编号 | 规则 | 权重 | 抓什么 |
| --- | --- | --- | --- |
| R1 | 未授权命中 CI lint 端点 | 30 | 匿名请求打到 `/ci/lint` 等路径 |
| R2 | 正则形态异常 | 35 | 内联注释标记 `(?#...)`、嵌套量词、超长正则 |
| R3 | 编码异常 | 15 | 非 ASCII / UTF-8 编码段、异常百分号编码 |
| R4 | 行为异常 | 25 | 120 秒内 ≥4 次 lint（爆破式探测）、lint 后 60 秒内出现 5xx |
| R5 | 组合加权 | 10 | 公开项目分支引用 + 任一其他信号同时出现 |

评分：同一 IP 命中多条规则时按 `1 − Π(1 − 权重)` 合并，封顶 100。

## 局限

- 启发式规则会有误报（比如安全研究员的合规扫描），高分 IP 建议人工复核后再封禁。
- 只看 HTTP 访问日志层面的痕迹，不分析 `.gitlab-ci.yml` 内容本身。
