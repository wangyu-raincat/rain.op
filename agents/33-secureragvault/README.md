# SecureRAGVault · 带权限过滤与引用溯源的安全知识库问答

`rain.op` 每日安全小 Agent 系列 Day 33：**安全 RAG** 方向。

一句话：把「谁能看到什么」做成检索的前置条件——权限过滤先于检索、答案强制带引用、机密问答接人工审批点，专治普通 RAG 最容易被忽略的越权召回问题。纯 Python 标准库，离线可运行，不联网、不调用任何外部 API。

## 它解决什么问题

普通 RAG 有个常被忽略的洞：**检索发生在权限过滤之前**。低权限用户问一个问题，系统先把全库最相关的文档召回、排序、摘要，再事后打码——高密级内容已经通过排序、片段、续写等侧信道泄露了。SecureRAGVault 把顺序倒过来。

## 核心功能

- **权限过滤先于检索**：访客 / 工程师 / 安全管理员三档角色，文档分公开 / 内部 / 机密三级。无权文档根本不进入候选集，而不是召回后再隐藏。
- **越权召回拦截提示**：若不过滤本会排进结果的高密级文档，会被显式列出「已拦截」，让侧信道风险可见、可审计。
- **答案强制带引用**：每条回答都标注来源编号与密级，无来源的句子不输出，引用溯源可核查。
- **机密问答人工审批点**：命中机密内容的回答默认暂扣，需加 `--approve` 显式确认才放行，生产落地时可替换为真实审批流。
- **提示注入隔离**：知识库文档里的指令只是数据。内置文档 KB-12 藏了一句注入文本，系统只做抽取式引用，从不执行文档里的指令。
- **批量越权审计**：`--audit` 用 9 个探针问题逐角色提问（共 27 次），输出越权召回拦截率，可作回归基线。

知识库内置 12 条文档：4 条公开（SQL 注入、钓鱼、密码、XSS）、4 条内部（VPN 接入、代码审计、应急响应、日志留存）、4 条机密（凭证轮换、红队报告、密钥管理、WAF 复盘）。

## 快速开始

环境：Python 3.8+，无第三方依赖（见 `requirements.txt`）。

```bash
cd agents/33-secureragvault

# 演示：同一问题，三种角色，三种可见范围 + 提示注入隔离
python secureragvault.py --demo

# 按角色提问
python secureragvault.py --ask "生产数据库的凭证怎么轮换？" --role guest
python secureragvault.py --ask "生产数据库的凭证怎么轮换？" --role admin --approve

# 批量越权探测，输出拦截率报告
python secureragvault.py --audit

# 列出某角色可见的文档
python secureragvault.py --list --role engineer
```

`--role` 三档：`guest`（访客，仅公开）、`engineer`（工程师，公开+内部）、`admin`（安全管理员，全部）。也可以用 `--kb` 指定自己的知识库 JSON（格式见 `kb.json`：`{"docs": [{"id", "level", "roles", "title", "text"}]}`）。

每次查询、每次越权召回拦截、每次机密答案暂扣都会写进程序目录下的 `audit.jsonl`；`--audit` 另行写出 `audit_report.json`。

```text
└── tests/
├── conftest.py
└── test_secureragvault.py # 12 个用例：切分、权限过滤、检索排序、注入隔离、审计留痕
```

运行时生成：`audit.jsonl`（审计日志）、`audit_report.json`（`--audit` 报告）。

## 设计要点

- **过滤与检索严格分两步**：`visible_docs()` 先按「密级 ≤ 角色 clearance 且角色在文档 roles 内」双重条件过滤，`search()` 只在过滤后的集合上打分——权限是检索的输入条件，不是输出的后处理，侧信道在结构上被堵死。
- **拦截清单来自对照检索**：问答时额外在全库跑一次同题检索，差集即「若不过滤本会泄露」的文档，把不可见的越权风险变成一条可留痕的审计事件。
- **抽取式回答天然抗注入**：回答只能从可见文档里挑原句并附引用，不生成、不执行任何文本——文档里的指令再像指令，也只是一段可被引用的数据。

## 对口的 JD 关键词

权限过滤、引用溯源、提示注入、工具调用审计、最小权限、人工审批点、评测通过率、Agent 工程化落地。RAG 落地时最容易出事的不是检索精度，而是**权限边界**：这个 agent 把"谁能看到什么"做成检索前置条件，并用可复现的审计探针把它变成回归指标。

## 边界说明

- 检索是词项匹配（中文单字 + 二元字串），不是语义理解；换个关键词往往能命中更相关的文档。
- 角色与密级是演示用的三档模型，落地时应接真实的身份系统与文档分级标准；`--approve` 只是演示审批点，需替换为真实审批流。
- 审计日志 `audit.jsonl` 写在程序目录下，生产环境请接入集中日志平台并做好访问控制。
- 知识库内容为通用安全实践示例，不针对某个真实系统做合规结论。
