# CloudSecQA

云安全配置离线问答：针对云账号最常见的 12 类配置风险做知识检索与抽取式回答，纯标准库，离线可运行，不联网、不调用外部 API。

## 它是做什么的

云上的风险大多不在某个 0day，而在配置：权限给宽了、存储桶公开了、密钥写进代码了、管理端口放行了全网。CloudSecQA 内置 12 张知识卡片，覆盖：

- IAM 过度授权、根账号保护与 MFA 缺失
- 公开存储桶、数据与备份未加密
- 云元数据 SSRF、AK/SK 泄露应急
- 安全组放行公网管理端口、网络隔离与流日志缺失
- 审计日志缺失、闲置账号与僵尸资源
- 跨账号信任过宽、密钥管理与凭据分离

## 怎么跑

```bash
python agents/31-cloudsecqa/cloudsecqa.py --demo
python agents/31-cloudsecqa/cloudsecqa.py --ask "存储桶公开了怎么处理？"
python agents/31-cloudsecqa/cloudsecqa.py --list
```

`--ask` 会按词项重叠打分（标题命中权重最高），输出最相关的卡片原文并标注卡片编号与匹配分，便于核对来源。也可以用 `--kb` 指定自己的知识库 JSON（格式见 `kb.json`：`{"cards": [{"id", "title", "text", "tags"}]}`）。

## 示例输出

```text
问题：存储桶公开了怎么处理？

[1] 【C02】公开存储桶导致数据泄露（匹配分 32）
存储桶公开是最容易造成大规模数据泄露的云配置：存储桶策略或 ACL 一旦允许任何人读取……
标签：存储桶、对象存储、公开访问、数据泄露
```

## 边界说明

- 知识卡片讲的是通用云配置防御思路，不针对某个云厂商或具体账号做审计结论。
- 检索是词项匹配，不是语义理解；换个关键词往往能命中更相关的卡片。
- 落地到自家云账号时，请结合实际的 IAM 策略、存储桶策略与审计日志复核，泄露类事件先停用凭证、再查日志确认影响范围。
