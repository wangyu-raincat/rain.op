# SupplyChain-QA — 供应链投毒事件速查

核心案例：**Rank Math SEO PRO 供应链投毒**（CVE-2026-111862，CVSS 9.8，
正在在野利用，2026-10-17 披露）——回答研判 / 自查 / 处置三连问：

- **我是不是中招了**：`--triage` 按下载/更新时间对照投毒窗口研判
- **怎么自查**：`--check` 沦陷指示器（IOC）+ 自查清单
- **密钥要换哪些 / 怎么修**：`--fix` 完整处置链（按整站沦陷处理）
- **怎么防下一次**：`--prevent` 供应链防护四条（签名校验、官方渠道、版本冻结灰度、更新后冒烟检查）

检索用 BM25（中英双语分词），支持 CVE 编号精确查 + 中文自然语言提问，
纯 Python 标准库，无第三方依赖。

## 事件速览

| 项 | 内容 |
| --- | --- |
| CVE | CVE-2026-111862（CVSS 9.8，在野利用中） |
| 投毒窗口（UTC） | 2026-10-15 20:02 → 2026-10-16 07:12 |
| 影响版本 | 3.0.123（**窗口内**下载/更新的包被植入；窗口外下载的不算沦陷） |
| 干净版本 | 3.0.124 |
| 后门行为 | C2 域名 `rank1cdn[.]com`；页面访问时重建隐藏 PHP 后门；建未授权管理员账号；伪造 WP core 文件；投放可执行 `.cache`；注册系统 cron 标记；窃取 WP 凭证/数据库密码/API keys；3 个恶意 `wp_options` 键 |

## 怎么跑

```bash
python supplychain.py --demo
```

离线可运行：`--demo` 演示两个研判场景（窗口内更新→判沦陷并给处置链；
窗口外下载→判未命中）+ 两次自然语言提问，纯标准库。

常用姿势：

```bash
# 研判：我的 3.0.123 是某时下载/更新的，中招了吗？
python supplychain.py --triage "2026-10-16 03:00Z" --version 3.0.123
python supplychain.py --triage "2026-10-16 11:00" --version 3.0.123   # 北京时间也行

# 自查 / 处置 / 防护
python supplychain.py --check
python supplychain.py --fix
python supplychain.py --prevent

# 自然语言提问
python supplychain.py "我是不是中招了"
python supplychain.py "密钥要换哪些"
python supplychain.py "怎么防下一次"
python supplychain.py CVE-2026-111862
```

## 研判逻辑

```
版本 ≥ 3.0.124                    → 本次事件未命中（干净版本）
版本 < 3.0.123                     → 本次事件未命中（早于被投毒版本）
版本 = 3.0.123 且时间在窗口内     → 视为沦陷（给完整处置链）
版本 = 3.0.123 且时间在窗口外     → 本次事件未命中（仍建议升级+自查）
版本 = 3.0.123 但时间缺失/解析失败 → 信息不足，给自查清单
```

## 与 Day 10 VulnIntel-QA、Day 12 LiveFire-QA 的区别

- **VulnIntel-QA**：通用 CVE 情报问答（影响范围/利用条件/修复版本）。
- **LiveFire-QA**：聚焦"正在着火"的漏洞——哪个最该先修、没补丁怎么缓。
- **SupplyChain-QA**：聚焦**供应链投毒这一类事件**的应急响应——按时间窗口研判
  沦陷、IOC 自查、处置链、以及下一次的防护。它不问"这个 CVE 严不严重"，
  问的是"我中招了吗、现在该干什么"。
