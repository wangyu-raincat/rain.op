# VeloQA — Arista VeloCloud Orchestrator 问答与版本研判

针对 **CVE-2026-114625**（Arista VeloCloud Orchestrator SQL 注入，CWE-89，
CVSS 3.1 9.9 / CVSS 4.0 9.4，关键级）的离线小工具：输入版本号判是否中招，
用自然语言问利用条件、托管版、Edge、7.0 等易错点。纯 Python 标准库，
离线可跑，不依赖任何 API Key。

## 这个 agent 是做什么的

- **版本研判**：按分支对照修复版本，判断某 on-prem VCO 版本是否仍受本漏洞影响。
  修复版本必须按分支一一对应：5.2.x 线 → 5.2.3.18；6.1.x 线 → 6.1.3.10；
  6.4.x 线 → 6.4.2.12。
- **离线问答**：在本地 `kb.json`（10 张情报卡片）中做词项匹配检索，
  回答利用条件、在野状态、修复版本、易错点和处置清单。
- **防踩坑**：专门覆盖几个易错点——修了 9 月 CVE-2026-93952 的
  5.2.3.16 / 6.4.2.8 不能修本漏洞；托管版厂商已打补丁但仍要查账号；
  Edge / Gateway 不受影响；VCO 7.0 未列出、不要判为安全。

## 怎么跑

```bash
cd agents/23-veloqa
python veloqa.py --demo
python veloqa.py --check 5.2.3.16
python veloqa.py --ask "只读账号能不能打？"
```

`--check` 判为“仍受影响”时按设计返回退出码 1（表示需要处理），
其余情况返回 0。`--ask` 可用 `--kb` 指定别的知识库 JSON。

## 示例输出

```text
$ python veloqa.py --check 5.2.3.16
版本研判：5.2.3.16
结论：仍受影响
说明：该版本低于本分支修复版本 5.2.3.18，仍受 CVE-2026-114625 影响，
请升级到 5.2.3.18 或更高。注意：该版本只修复了 9 月的 CVE-2026-93952，
不能修复本漏洞！

$ python veloqa.py --ask "托管版还要不要管？"
问题：托管版还要不要管？
[1] 托管版 / Dedicated 版：厂商已打补丁，但仍要核查（匹配分 8，卡片 velo-06）
    托管版 / Dedicated 版 VCO 由 Arista 已打补丁，厂商侧已修复。
    但仍要核查账号与近期管理操作……
```

演示（`--demo`）会依次跑 6 个版本研判（含 7.0 的“未确认”）和 4 个典型问答。

## 知识来源与边界

- Arista 安全公告 0199（经多家转述）：评分、利用条件、修复版本、托管版已修复。
- CISA KEV：2026-10-23 列入，联邦机构修复截止 2026-10-26；Arista 称正在被积极利用，
  但未公开利用技术细节、受影响机构数量与归因。
- 这是 2026 年以来第三个被武器化的 VCO 漏洞，前两个是 7 月的 CVE-2026-16812
  与 9 月的 CVE-2026-93952；不要和 Day 15 的 Collabora CVE-2026-110447 混淆。
- 边界：知识库是离线快照，不代表最新情报；“未确认”分支（如 7.0）请向 Arista TAC 确认，
  不要当作安全；处置前请以厂商公告和 CISA KEV 复核。
